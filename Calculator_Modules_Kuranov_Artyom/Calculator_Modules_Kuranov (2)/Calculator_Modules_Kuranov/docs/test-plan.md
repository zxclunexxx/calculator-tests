# План тестирования

**Проект:** Консольный калькулятор.  
**Предмет:** Поддержка и тестирование программных модулей.  
**Автор:** Куранов Артем, РПО-3.

## 1. Основание и область проверки

План развивает предыдущую работу «Разработка программы тестирования программного продукта. Вариант А. Консольный калькулятор». Её извлечённый текст сохранён в [previous-test-plan.txt](previous-test-plan.txt).

В предыдущем плане явно указаны пары `5, 2`, `-6, 3`, `0, 4`, `8, 0`; эти данные сохранены. Буквы и слишком большие числа названы без конкретных строк: `abc`, `2147483648` и другие значения ниже являются конкретизацией этих сценариев. Проверки пустой строки, границ `int`, конца потока и текста после числа добавлены в рамках требования текущей практической о граничных и негативных тестах.

Исходного кода предыдущей версии не было. Проверяется новая реализация по описанию, а не доказательство неизменности неизвестного исходника. Обработка неправильного ввода добавлена по прежнему плану. История вычислений остаётся дальнейшей доработкой: её контракт и сценарии не определены, в число выполненных проверок она не входит.

## 2. Правила программы

- Два 32-битных целых входа; каждое число вводится с новой строки.
- Сразу вычисляются сумма, разность, произведение и частное.
- Целые результаты имеют тип `long long`; частное имеет тип `double`.
- Нулевой делитель запрещён. В консоли выводится «На ноль делить нельзя»; прямой вызов `Divide` вызывает `std::invalid_argument` с тем же текстом.
- Ошибочный ввод отклоняется целиком и запрашивается повторно. `ParseInteger` при ошибке сохраняет прежнее значение выходного аргумента.
- Конец входного потока прерывает получение пары без вычисления результата.

В таблицах `MIN = -2147483648`, `MAX = 2147483647`; четыре результата перечислены в порядке «сумма; разность; произведение; частное». Число тестов означает число методов `TEST_METHOD`; внутри одного метода может быть несколько проверок одного сценария.
