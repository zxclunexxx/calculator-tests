# Объяснение проекта

## Почему файлов несколько

Модуль - часть программы с одной понятной задачей. В этом проекте ввод проверяет данные, вычисления возвращают числа, а вывод формирует текст.

В файле `calculation.h` написано объявление:

```cpp
long long Sum(int first, int second);
```

Оно сообщает, как вызвать функцию и какой результат она вернёт. В `calculation.cpp` находится реализация:

```cpp
long long Sum(int first, int second)
{
    return static_cast<long long>(first) + second;
}
```

`#include "calculation.h"` подключает объявление. Сам `.cpp` собирается как отдельный исходный файл проекта. Подключать `.cpp` через `#include` не требуется.

`#pragma once` в начале заголовка защищает от его повторного подключения в одном исходном файле.

## Что делает main

`main` настраивает русский текст для консоли Windows, объявляет два числа, выводит приглашение, вызывает `ReadNumbers`, затем `PrintResults`. Арифметических формул и разбора строки в `main` нет.

`#ifdef _WIN32` означает «скомпилировать этот участок только для Windows». В Windows вызываются `SetConsoleCP` и `SetConsoleOutputCP`; в другой системе этот служебный участок пропускается. На алгоритм калькулятора условие не влияет.

## Почему long long и double

В Windows `int` хранит числа от -2147483648 до 2147483647. Но сумма двух допустимых `int` может выйти за этот диапазон. Поэтому сумма, разность и произведение возвращаются в `long long`.

Преобразование `static_cast<long long>(first)` выполняется **до операции**. Если сначала умножить два `int`, а потом присвоить результат в `long long`, переполнение уже могло бы произойти.

Для деления используется `static_cast<double>(first) / second`. Поэтому `5 / 2` даёт `2.5`, а не целое `2`.

## Как обрабатывается деление на ноль

При обычном выводе `FormatResults` проверяет второй аргумент. Если он равен нулю, выводится требуемое сообщение.

Кроме этого, сама функция `Divide` защищена: прямой вызов с нулём вызывает исключение `std::invalid_argument`. Это позволяет тестировать функцию напрямую и не получать неверный результат. Ноль как условный признак ошибки здесь не подходит: `0 / 4` законно возвращает ноль.

В Microsoft Unit Tests тип исключения проверяется так:

```cpp
Assert::ExpectException<std::invalid_argument>([]
{
    Divide(8, 0);
});
```

`[] { ... }` - небольшая функция без имени. Тестовый фреймворк вызывает её и проверяет, возникло ли указанное исключение.

## Как проверяется ввод

`std::getline` получает строку целиком. `ParseInteger` создаёт `std::istringstream` - поток чтения из этой строки - и пытается прочитать целое число. Затем проверяется, не осталось ли другого непробельного символа.

Поэтому `12abc`, `2.5` и `5 2` отклоняются полностью. Пустая строка, буквы и выход за диапазон `int` также дают `false`. Если разбор успешен, функция записывает значение в аргумент `int& number` и возвращает `true`.

Знак `&` в параметре означает передачу по ссылке: функция может изменить переменную вызывающего кода. Здесь значение меняется только после успешной проверки. При ошибке старое значение сохраняется.

`ReadInteger` повторяет запрос, пока не получит правильное значение или конец входного потока. `ReadNumbers` вызывает её сначала для первого, затем для второго числа.

`std::numeric_limits<int>::min()` и `max()` дают допустимые границы типа для текста ошибки.

## Зачем передавать потоки

В приложении функции получают `std::cin` и `std::cout`. В тестах вместо консоли можно передать `std::istringstream` с заранее подготовленным вводом и `std::ostringstream` для получения вывода как строки.

Это позволяет автоматически проверить повторный ввод и точный текст сообщений без ручного набора в консоли. Сам алгоритм при этом используется тот же.

`std::ostringstream` также применяется в `FormatResults`, чтобы сначала собрать весь результат в строку. `std::setprecision(15)` задаёт до 15 значащих цифр для дробного результата. Классическая локаль обеспечивает точку в дробной записи.

## Как читать тесты

`TEST_CLASS` объединяет тесты одного модуля. Каждый `TEST_METHOD` - отдельный сценарий. Внутри идут подготовка данных, вызов функции и проверка результата: Arrange, Act, Assert.

```cpp
const int first = 5;
const int second = 2;

const long long result = Sum(first, second);

Assert::AreEqual(7LL, result);
```

`7LL` - число 7 типа `long long`. Сначала в `AreEqual` передаётся ожидаемое значение, затем фактическое. Для `double` дополнительно задаётся допустимая погрешность `0.000000000001`.

Тесты создают свои переменные и потоки внутри каждого метода. Отдельная подготовка через `TEST_METHOD_INITIALIZE` и очистка здесь не нужны: динамических ресурсов и общей истории нет.
